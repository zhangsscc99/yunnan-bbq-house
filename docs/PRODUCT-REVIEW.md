### 我能做的（Capability）
- 摇杆 8 向移动、单动作键完成「取料→切→烤→取」全链：实测拿五花肉生串 → 砧板切 3 刀 → 上烤炉 → 6.6s 后 `stage=cooked, done=true` → 按「取烤串」成功拿到熟串，全程 0 JS 错误。
- 烤炉 3 位独立计时、砧板 0/3→3/3 进度条、订单气泡按菜品名区分、结算数据源（`__game.money/served/angry/waste`）齐备。
- 部署链路现在是通的：`/bbq/` 200、`/bbq/api/health` 200。

### 我看不懂的（Clarity）
1. **开局按钮是灰的「去料箱取料」**。玩家出生点 (0.5, 1.2) 距烤炉 `usePos`(1, 1.5) 只有 **0.58m**，落在 GAME-DESIGN §6 的 1.15m 判定圈内，于是“站在烤炉前、两手空空”的语义被命中，显示的是提示语而非可执行动作；玩家第一次点它百分百没反应（实测点击后手臂/物件无变化，只有按钮描边闪 0.25s）。
2. **订单卡与气泡的关系**：气泡显示菜名+耐心环，右上订单卡只对 `seated/eating` 生效（`hud.ts setOrders`）。顾客在 `walking-in` 时头顶已有菜名、右上没卡，玩家会以为“那两个单子不用管”。
3. **「烤制中…」出现在玩家没有放东西的时候**（旧构建在出生点就显示，新构建已改为 `nextStep` 提示）——这条在新构建上已不复现，记录为已修。

### 让我不爽的（Friction）
1. 竖屏下**烤串只有几个像素**（截图实测：串长 ≈19px、粗 1–4px，烤炉进度条 0.34×0.045m ≈ **16×2px**），熟没熟完全看不出来；我只能靠 `__game.grill.slots[i].item.grillT` 数值判断——这不该是玩家要做的事。
2. 切一串 5 次点按，中间没有任何“连击/蓄力”替代路径；第 5 次要“把串拿起来”，和第 1 次“放上去”用的是同一个按钮，语义反复横跳。
3. 屏边气泡被裁：实测 3 位顾客时，左侧气泡 `x=-63, w=84`，屏幕上只剩 21px 的「菌子」两个字贴在左边缘，像一条渲染错误。

### 让我想继续玩的（Hook）
- 炭火炉那圈橙红光 + 烟往上飘，是真实“想再烤一串”的画面诱因；料箱→砧板→炉子→盘的物理动线成立，横屏时真有 OC 的忙乱感。
- 菜单价目（¥48/¥32/¥26）+ “3 分钟 ¥180” 的目标给了明确的短期 KPI，属于可复用的强钩子。

3. **出生点落在烤炉交互圈内**（设计文档自相矛盾）
   - GAME-DESIGN §5 写出生点 (6, 5.5)，§6 写判定 1.15m，而烤炉 `usePos`=(7,6) → 理论距离 1.12m < 1.15m，**按文档实现也必然开局命中烤炉**。实测 (0.5,1.2) 与 (1,1.5) 距离 0.58m。

### P2 打磨项
1. `#bbq-act .cap` 10px / 订单卡 `.pr` 11px / 顶部 `.k` 12px，均低于 ART §5「HUD ≥13px」；建议 caption 12px + 图标 28px。
2. 首屏背景被压暗 + 强模糊，认不出店面（vision：“糊成一片”）；建议保留一条可见的烤炉/餐桌亮区，或在弹窗左侧放一帧静物特写。
3. 菜单黑板字与底色对比不足，等于装饰；至少让三行菜名可读。
4. 左上遮阳篷/布幔边缘锯齿破碎（`land-02-start` 左上角）。
5. 切配可加长按连切（≥0.25s 按住自动推进），5 次点按 → 1 次按住。
6. 无加载指示：软件渲染下首帧 6–17s 是纯黑背景；真机基线未知，建议首屏先出 HUD 骨架 + 进度点。
7. **公网 `/bbq/api/health` 返回 index.html（200 假阳性）**：本机 `127.0.0.1:3035/api/health` 正常返回 `{"ok":true}`，但经 proxy 后 `/bbq/api/health` 落到 SPA 兜底。外部监控若打这个地址会永远“健康”。**验收：**公网该路径返回 `application/json` + `{"ok":true}`，或监控改用 `/bbq/assets/<hash>.js` 200 + 首帧 `__game.phase` 双重校验。
