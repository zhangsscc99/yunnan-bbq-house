### P1 明显缺陷
1. **线上 bundle 落后 main 两个提交，修复未生效**（新 → **B-055**，本轮首次记录）
   - 事实：`curl http://127.0.0.1:3035/bbq/` 与公网都返回 `assets/index-ChCgL6cA.js`；`server/dist/index.html` 时间戳 **02:59**；仓库 `dist/index.html` 已指向 **`index-CzoVCdZb.js`（04:09）**。`server/dist/assets/index-ChCgL6cA.js` 里 **没有** `bbq-popup-hold` 字样（`grep -c` = 0），而 `4832afd` 的 `src/ui/hud.ts` 有 `.popup{font-size:24px;…animation:bbq-popup-hold 2.2s}`。
   - 复现：`curl -s https://openfolio.uk/bbq/ | grep -o 'assets/index-[^"]*js'`；再 `grep -c bbq-popup-hold /tmp/live.js` → 0。
   - **验收：** ① 每次构建/部署后 `server/dist/index.html` 引用的 hash 必须等于刚 build 出的 hash（脚本断言，失败即部署失败并回滚）；② 页面把构建 hash 打到 `console.info('[bbq] build', __BUILD__)` 且 `window.__build` 可读，走查报告必须写明测的是哪个 hash；③ 本轮之后任意一次 `curl` 的 hash 必须与 HEAD 构建一致。
2. **首屏（菜单态）露出对局控件与 HUD 残影**（新 → **B-056**）
   - 复现：加载后在 `phase === 'menu'` 时读 `#bbq-stick` / `#bbq-act` / `#bbq-hud .topbar` → `{display:'block',opacity:'0.85'}` / `{display:'flex',opacity:'0.55'}` / `{w:315,h:36}`，全部 `visible:true`；截图 `port-01-title.png` / `land-01-title.png`（vision：「底部露出两个摇杆区域」「顶部和底部残留模糊 HUD/按钮轮廓，形成视觉噪声」）。
   - **验收：** `phase !== 'playing'` 的任意时刻，`#bbq-stick`、`#bbq-act` 的 `display` 为 `none`（或 `visibility:hidden`），`#bbq-hud .topbar` 的 `opacity ≤ 0.15`；e2e 断言菜单态三者皆不可见；双端各 1 帧 vision 不得再读出摇杆/按钮。
3. **没有任何进度存档，首屏也没有「继续」**（新 → **B-057**）
   - 复现：首屏 `localStorage` 为 `{}`；`JSON.stringify(Object.keys(localStorage).filter(k=>k.startsWith('bbq')))` → `[]`；结算「进入第 2 关」后 `bbq.level='2'`，刷新页面回到 `第 1 关 / ¥0`，且首屏按钮文案仍是「开 店」。
   - **验收：** 关卡结束写 `bbq.level` / `bbq.best`；重载后首屏出现「继续（第 N 关 · 最佳 ¥X）」主按钮 +「重新开始」次按钮；点继续 → `level === N`、`money === 0`、`target` 对应 N；e2e 断言刷新前后 `level` 一致。
4. **顾客点单气泡没有夹紧视口，最右两桌直接看不见**（新 → **B-058**）
   - 复现：`spawnNow('pork'|'mixian'|'mushroom')` ×3 → 走到 `seated`；读 `#bbq-bubbles .bubble` 的 `getBoundingClientRect()`：`[367,250,120,34]`（right **487** > 390，裁 97px）、`[404,250,72,17]`（`x≥390`，**完全在屏外**）。截图 `port-03-orders3.png`（vision：「最右侧有一个被边缘裁掉一部分的圆形气泡」）。
   - **验收：** 双端 8 个机位（4 桌 × 双端）下，任一 `.bubble` 的 `left ≥ 4` 且 `right ≤ vw-4`（超出时整体平移，指针三角仍指顾客）；e2e 断言 4 桌全坐满时 0 个气泡越界；连跑 3 次。
5. **飘字出生即 `opacity:0`、生命周期 0.85s，肉眼与截图都抓不到**（B-039 / B-047 合并复现，各第 2 / 5 次）
   - 复现：`setPatience(0.05)` + `tick(0.05,4)` 触发 3 人离店，按 0/150/400/900ms 采样 `.popup` 计算样式 → `opacity` 依次 **`0 / 0 / 0 / (节点消失)`**、`font-size 17px`、`animation bbq-rise 0.85s`；`port-04/05/06` 三帧 vision 一致判「没有愤怒离店/没有 -1/没有光效，像什么都没发生」。
   - **验收：**（与 B-047 同一口径，本轮补充）popup 出生当帧 `opacity ≥ 0.85`；存在时长 ≥1.6s；上菜/离店后 300ms 的截图 vision 必须能读出金额或「-1」；4 人同帧离店时 4 条 popup 的 rect **互不重叠**（见 B-059）。

### P1 明显缺陷
1. **低帧设备上游戏时钟只有墙钟的 7–10%**（B-035，**第 2 次量化**）
   - 复现：`load 12.2 / 4 核`，软渲染 1fps；开局后静置 6.03s（期间 6 帧），`timeLeft` 180 → 179.4（Δ0.60s）；横屏 6.08s / 4 帧 → Δ0.40s。按住摇杆 29.5s 墙钟 → 位移 4.18m（22 帧）。
   - 根因仍在 `src/main.ts` 的 `dt = Math.min(getDelta(), 0.1)`：1fps 时每帧只推进 0.1s，游戏时钟 = 1fps × 0.1s = **0.1×**；这就是「180 秒关卡实际跑 30 分钟而 HUD 写着 3:00」。
   - **验收：** 低帧（≤5fps）下静置 60s 墙钟，断言 `timeLeft` 减少 ≥54s（≤10% 误差）；同条件按住摇杆 2s 墙钟位移 ≥5.5m；60fps 下既有断言全绿。参考 `GAME-DESIGN §6`（3.2 m/s）、`TECH-STACK §4`（一切走 `flow.update(dt)`）。
2. **横屏左侧 18.7% 死黑且随镜头换边**（B-025，**第 5 次量到**，新增"换边"证据）
   - 复现：横屏 844×390 开局不动 → `land-02-playing.png`：左 0–160 列均值 28.0、右 160 列 93.1、连续 158 列 <55；角色移动后再截 `land-07-hud.png`：暗列降到 113 且**最右列亮度 22**。
   - 确定性：同一会话两帧黑边位置不同 → 相机横向没有夹紧在世界边界（`ART-DIRECTION §1` 的 `halfH` 公式在 844×390 给出约 20.7m 宽视野，而 `GAME-DESIGN §5` 世界只有 12×9m）。
   - **验收：** 双端 × `teleport(±5,±4.5)` 四角共 8 帧，任一帧都不存在连续 ≥24 列且亮度 <26 的区域；左右（或上下）暗区宽度差 ≤8px；连跑 3 次稳定。
3. **首屏 `blur(3px)` 把美术藏起来，结算面板也把顶部 HUD 糊掉**（B-036，**第 6 次**）
   - 复现：`getComputedStyle(.bbq-panel)` → `backdrop-filter: blur(3px)`、`background-color: rgba(12,8,5,.45)`；`port-01` / `land-01` 两次 vision 均判"场景不可辨认"；`port-14` 顶部 140px 放大后状态条文字不可读。
   - **验收：** 遮罩降到 `blur(1px)` / `rgba(12,8,5,.28)`；首屏相机取景对准「烤炉 + 炉上串 + 一位顾客」；vision 只看首屏能说出「烤炉/桌子/角色」中至少两个；结算面板顶部 140px 内状态条文字可读（或干脆在结算时隐藏 HUD）。参考 `ART-DIRECTION §1/§3`。
